## 已完成：usage 包 10 个客户端测试失败（jsdom 选择器）

- 现象：`entry.spec.tsx`(2) / `usage-entry.client.spec.tsx`(3) / `usage-modal.client.spec.tsx`(5)，
  统一 `SyntaxError: '*+:where(ul, ol))' is not a valid selector`（nwsapi，由 getByRole →
  getComputedStyle → jsdom 样式级联匹配触发；栈底是 `el.matches()`）。
- 已确认：新 ui-primitives `lib/markdown/MarkdownText.module.css` 含 `:where(ul, ol)`、
  `:has(+ :where(ul, ol))` 等**括号内带逗号**的选择器；jsdom 的 CSS 解析器（rrweb-cssom）朴素按逗号
  切分选择器列表 → 产生非法片段。旧版宿主 CSS 无此类选择器所以不炸。
- **已闭环**：两包 vitest.config.ts 的 `css.include` 收窄到本包 src 的 `*.module.css`
  （usage：`packages[\\/]usage[\\/]src[\\/].*\.module\.css$`；toolkit 同款），宿主 ui-primitives 的 CSS
  不再注入 jsdom，坏 CSS 注入路径无需再追。toolkit 的 client spec 亦以同款收窄规避。
- 注意 usage vitest.config.ts 的 `css.modules.classNameStrategy: 'non-scoped'` 是 entry.spec 断言
  `rail` class 的前提，改动 css 配置时勿破坏。
