# 飞书卡片改造设计：去标题 + 过程折叠区 + 状态标记 + 双流式

日期：2026-08-25
包：`packages/project-bot`（飞书渠道，`src/channels/feishu/` + `src/core/outbound.ts`）

## 背景与目标

现有实现：JSON 2.0 流式卡片，header 带 title + template 状态色（蓝/绿/红/灰），正文单 markdown 元素流式更新，满 `cardMaxBytes` 自动拆续卡，定格时整卡 replace 换头色。`assistant/message` 事件的 `reasoning` / `tool_call` 块目前被丢弃。

本次改造四条需求（已与需求方确认）：

1. **删除卡片 title**：整个 `header` 字段删除，连带放弃状态色条。
2. **增加思考和工具调用过程输出**：`reasoning` 全文 + 工具调用摘要行（工具名 + 参数），放进折叠面板，默认收起。
3. **增加输出过程和输出完成标记**：文字状态行替代原色条（`⏳ 输出中…` → `✅ 输出完成` / `❌ 输出出错` / `⏹ 已取消`）。
4. **流式输出**：正文保持现有打字机流式；过程区也随事件增量更新。

## 方案

单卡三元素（方案 A）。卡片结构：

```jsonc
{
  "schema": "2.0",
  // 无 header
  "config": { "streaming_mode": true, "summary": { "content": "生成中…" }, "streaming_config": { /* 现状不变 */ } },
  "body": {
    "elements": [
      {
        "tag": "collapsible_panel",
        "expanded": false,  // 默认收起
        "header": { "title": { "tag": "plain_text", "content": "思考与工具调用过程" } },
        "elements": [{ "tag": "markdown", "element_id": "process", "content": "" }]
      },
      { "tag": "markdown", "element_id": "md", "content": "" },      // 回答正文
      { "tag": "markdown", "element_id": "status", "content": "⏳ 输出中…" }
    ]
  }
}
```

三个元素各带 `element_id`，过程区与状态行走 cardkit 元素级增量更新（`cardElement.content`），正文保持现有打字机流式更新。

**已核实**（飞书开放平台文档）：`collapsible_panel` 默认收起；流式模式下卡片/组件级 OpenAPI 均可连续调用；元素级内容更新按 `element_id` 定位 markdown 组件。

**风险与兜底**：文档未明说折叠面板**内嵌** markdown 能否用元素级 API 更新。实现后在开发回路实测一次；若不支持，过程区退化为整卡 replace 更新（仅 plan 层策略变化，架构不变）。

## 改动点

### ① `src/channels/feishu/cards.ts`（纯函数层）

- `buildCardJson`：删除 `header`；body 改为上述三元素。新增常量 `PROCESS_ELEMENT_ID = 'process'`、`STATUS_ELEMENT_ID = 'status'`，保留 `CARD_ELEMENT_ID = 'md'`。
- 新增 `sliceTailByBytes(text, maxBytes)`：UTF-8 字节上限截尾（不劈开多字节字符/代理对），超限结果 = `…（已省略前文）\n` + 尾部。过程区专用。
- `StreamState` 增加 `processShownLen`（过程区已提交前缀长度）。
- `CardOp.update` 增加 `elementId` 字段（`updateCardElement` 按它路由到对应元素）。
- `planSync(state, answer, process, maxBytes, processMaxBytes)`：
  - 过程区：`process` 先经 `sliceTailByBytes` 截到 `processMaxBytes`，增量部分 `update` process 元素；
  - 正文：现有拆卡逻辑原样（`offset`/`shownLen`/满卡关流开续卡）；**续卡结构 = 正文 + 状态行，不带过程面板**；
  - `title` 参数删除。
- `planFinalize(state, status)`：产出 `settings(streaming:false)` + `update` status 元素为定格文案（不再整卡 replace）。定格文案：done → `✅ 输出完成`，error → `❌ 输出出错`，cancelled → `⏹ 已取消`。`CardTemplate` 类型删除。

### ② `src/core/outbound.ts`（数据流）

- 新增 `processOf(content)` 纯函数：`reasoning` 块取 `text` 全文追加；`tool_call` 块渲染为一行 `🔧 {name} — {JSON.stringify(arguments)，截断 120 字符}`。
- `turn.buffer` 拆为 `turn.answer` / `turn.process` 两个累积缓冲；`assistant/message` 事件为增量粒度，直接追加，无需去重。
- `rt.reply.update(snapshot)` 改为 `rt.reply.update(answerSnapshot, processSnapshot)`。
- turn 无正文但有过程输出时也要建卡（`beginTurn` 惰性语义变为「首次 update 任一缓冲非空即建卡」）。

### ③ `src/core/channel.ts`（接口）

- `ReplyHandle.update(markdown: string)` → `update(answer: string, process: string)`。ReplyHandle 只有飞书一个实现，直接改签名。
- `ChannelTunables` 增加 `processMaxBytes: number`。

### ④ `src/channels/feishu/reply.ts`（执行层）

- `update(answer, process)` 双缓冲、共用现有节流器 flush；`exec` 的 update 分支改用 `op.elementId`。
- finalize、错误重试、`PENDING_CARD_ID` 并发保护、无卡降级文本逻辑全部保留。

### ⑤ `src/index.ts`（Config）

- Config schema 增加 `processMaxBytes: z.number().default(8_000)`，透传进 `ChannelTunables`。

## 非目标

- 不引入工具返回结果进卡片（仅调用摘要行）。
- 不改动入站、鉴权、会话管理、表情回复逻辑。
- 过程面板标题（「思考与工具调用过程」）、工具摘要格式、状态文案按上文定案，不进 Config（后续有需求再提）。

## 测试

- `tests/feishu-cards.test.ts`：buildCardJson 无 header 且三元素齐全；planSync 过程区增量 update；过程区超 `processMaxBytes` 截尾带省略标记；正文拆卡后续卡无面板；planFinalize 三种状态文案 + 不再 replace。
- `tests/feishu-reply.test.ts`：op 序列带 elementId 路由到对应 API 调用；双缓冲节流合并。
- `tests/outbound*.test.ts`（按现有测试文件布局）：`processOf` 提取 reasoning/tool_call、参数截断；turn 缓冲分离。
- 全量回归：`pnpm --filter @dsh-agent-toolkit/project-bot test` + `typecheck` + `bundle`。

## 验证

开发回路（`pnpm dsh web --patch cordis.yml`）实测一次真实 turn：确认折叠面板内嵌元素可流式更新（风险点兜底验证）、默认收起、状态行定格正确。
