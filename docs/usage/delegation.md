# 并行委派（team_delegate）

委派让主 Agent 把独立子任务交给注册表中的成员角色执行：成员以一次性子 Agent 形态在前台运行，完成后把产出返回给主 Agent。浏览器半把每次委派渲染成一张实时卡片。

## 工作方式

主 Agent 的系统提示词里会自动注入一段「团队名册」（可用成员：`id: 描述`，排除 `main`），模型据此决定何时委派、委派给谁。名册内容实时读取注册表，在 Agents 面板改角色后立即生效。

模型调用 `team_delegate` 工具时传三个参数（皆必填）：

| 参数 | 说明 |
|---|---|
| `role` | 成员角色 id，必须来自名册（`main` 排除在外）。填了未知角色会报错并列出可用角色 |
| `description` | 3-5 词任务简述，用于卡片展示 |
| `prompt` | 完整自包含的任务书。**成员看不到主对话上下文**，任务背景、约束、验收标准都要写进 prompt |

执行语义：

- **一次性**：成员跑完即销毁，不保留会话供后续追问
- **前台等待**：主 Agent 阻塞等待成员完成，返回规范 JSON：`{kind:'foreground', role, runId, childSessionId, output}`
- **禁止套娃**：`maxDepth: 1`，成员不能再次委派（深度 2 会被 provider 响亮拒绝）
- **取消传递**：主会话被取消时，成员任务同步取消
- **异常转错误**：成员以 `aborted` / `error` / `max-tokens` / `refusal` 等非正常原因结束时，工具返回错误，并附上成员中断前的部分产出

成员的人格与能力来自注册表：`persona`（叠加委派契约段与能力守则）、`model`（若配置）、`tools.allow` 白名单（若配置）。细节见 [prompt-layers.md](prompt-layers.md)。

## 委派卡（web UI）

每次 `team_delegate` 调用渲染为一张卡片：

- 头部：角色 chip + 任务简述 + 状态点（执行中 / 成功 / 失败）
- 模型 chip：委派卡与子会话头部会显示子 Agent 使用的 `provider / model`（角色配置了模型覆盖则用之，否则继承主 Agent 路由）
- 展开：完整 prompt 与成员产出
- 成功且有子会话记录时，提供「查看子对话」按钮，打开该次委派的子会话

> 注意：委派卡按固定工具名 `team_delegate` 注册。如果你通过配置 `toolName` 改了工具名，卡片不再生效，会回落为通用工具展示。

## 使用建议

- 适合**相互独立、可并行**的子任务：让主 Agent 在一条消息里发起多次委派，即可并行执行
- 任务书要**自包含**：成员没有主对话记忆，引用"上面说的那个文件"会失败
- 用描述字段写清任务定位，方便在卡片列表里快速辨认

## 相关配置

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `provider` | `spawn` | 委派用的 subagent provider 名 |
| `toolName` | `team_delegate` | 工具对模型的可见名（见上方卡片注意事项） |

委派工具仅在 subagent provider 具备 `persona` + `depthLimit` 能力时挂载；provider 不在场时工具不可用（日志有提示），团队名册段仍会注入。
