# 飞书渠道（现行事实）

> 本文是该功能域**现行状态**的权威描述（2026-09-10 自 AGENTS.md 拆出）；改动该域时同步本文。「为什么这样设计」的决策考古见 `docs/superpowers/specs/archive/`。

## 入站、出站与发起人提示段

飞书入站支持 text/post/image 三类消息：图片经渠道懒下载（不占 WS 3 秒窗口）→ `tools.get` 式落 `ctx.attachments`（可选服务，缺席降级提示）→ image 内容块进 user message（0.2.6）；飞书出站为确认式状态机：planSync 返回逐 op commit，op 成功才提交状态；失败按错误码治理（300301 视同成功 / 200850·200510 重激活重放 / 200860 废弃拆卡续写 / 未知错误 seq+2 重放）；拆卡定格旧卡状态行「📦 内容较长，已接续到下一张卡片」；每张卡关流后全量重放整卡（非流式 update 直显，根治关流时打字机存量未渲染完；replace 失败非致命只记日志）；`cardMaxBytes`（默认 26000）语义为单卡真实 DSL 字节上限（平台硬上限 30KB），`cardPrintStep`（默认 5）控制打字机速度；reply 句柄在 in-flight 准入通过后才替换。忙时消息排队：任务执行中收到的非指令消息进 per-chat 内存队列（不限容量，重启即丢），notice 确认队位；turn/end 与 agent/error 释放槽位时经 Outbound onTurnIdle 回调同步排水（占槽转移先于删表情，保「inflight 空 ⇒ 队列空」无并发窗口），followup 抛错回滚同样先排水后 ack（否则窗口内新到消息插队到更早的排队消息之前）；bot 停止/解绑/删除时清空该 bot 全部 chat 的排队队列（条目持有渠道句柄，静默丢弃）；/new 与 /switch 完成后兜底补排（队列是 chat 级，/new 不清队列）；撤回原飞书消息即撤销排队条目（im.message.recalled_v1 事件按 messageId 匹配，仅排队中生效，撤回正在执行的消息静默忽略；扫码建应用 addons 已含该事件订阅，存量应用需在开发者后台补开）。`/new` 等旧卡 finalize 后再摘会话映射。bot 会话的 workspace 挂载为惰性（2026-09-17）：建账（create/resume/接管/switch）时不 attach，首条消息投递（会话由 blank 转 non-blank）时才 attach 一次（每进程幂等，失败仅 warn 且下条消息重试）——空白期不进 workspace，避免宿主 web「新会话」的 blank 复用启发式（connectWorkspace 复用 blank + cwd 匹配 + 已挂载的会话）把飞书绑定会话当新会话打开、消息与出站回流飞书；代价是 /new 后的空白会话在首条消息前不出现在 /sessions 与 web 侧边栏。bot 会话创建/恢复/重置时注入渠道发起人提示段 `dsh-agent-toolkit:channel:sender`（order 20，channel + 发起人 open_id；`feishu.injectSender` 开关默认 true；0.2.7）。

出站流式增量源（0.1.5 迁移）：app 级订阅 `agent/assistant-stream` 瞬态帧——`start` 帧校验 turn 并建 attempt 基线（chunk 帧不携带 turn/step，按基线归属当前 step），`chunk` 帧按 `text-delta`→正文 / `reasoning-delta`→过程 / `block-end(reasoning)`→过程段段落分隔分流入段，`end` 帧不消费；turn 生命周期仍由 `turn/start`/`turn/end` 驱动。帧为 fire-and-forget（丢帧无重传），持久 `assistant/message` 结算时对账「全部 text 块拼接（textOf）」有界恢复丢帧——`turn.lastTextStep` 命中结算 step 以权威全文替换，未命中但权威非空时 append 新 text 段补回（不篡改上一步已提交正文）；`assistant/attempt`（无表面消息）不消费。设计依据：`docs/superpowers/specs/archive/2026-09-10-feishu-stream-0.1.5-design.md`。生产调试日志：`feishu.debugLog`（默认 true）+ `debugLogDir`（默认 `~/.dsh/logs/feishu-debug/`）+ `debugLogRetentionDays`（默认 7），JSONL 按日滚动，事件含 op/close/replace/abandon/reconcile/frame-stats，内容只记长度+首尾 20 字。

运维指令面（0.3.1 起）：`/new` `/stop` `/status` 为整条精确匹配指令；/status 在队列非空时追加「排队（N）」段，全部列出、每条前 20 字（纯图片显示 [图片]）；/stop 只停当前任务不清队列（无任务但有排队时提示排队数）；`/sessions` 列出 bot 项目 workspace 候选会话（workspaceRegistry 候选 + live 会话标题，标题取不到显示 (无标题)，三服务缺席降级）；`/switch <序号|id前缀>` 把 chat 绑定覆盖到目标会话（序号指最近一次 /sessions 输出的 per-chat 内存缓存；目标在插件内存直接复用、在宿主内存存活（web 界面等持有写句柄）则接管复用（保持其当前装配，setup 不重跑）、冷会话才 resume 接管（套用 bot 装配）；binding 在接管/resume 成功后才覆盖；切走的旧 runtime 不 retire，在飞 turn 卡片照常收尾，闲置落定且未重新绑定后摘出 sessions）；`/doc <相对路径>` 把项目内文件以飞书文件消息发回会话（护栏：项目根内相对路径、lstat 拒绝链接、`feishu.docMaxBytes` 上限默认 30 MiB；应用需 `im:resource` 权限）；`/ls [相对路径] [关键字]` 单层罗列项目目录（树形连接符 + 类型图标 + 文件大小、目录在前按名称排序、100 条截断）；带关键字时在该子树递归按名称搜索（不分大小写、不追随符号链接、遍历上限 1 万条），输出「图标 + 相对项目根路径 + 大小」（复制给 /doc 需去掉首尾装饰）；护栏与 /doc 同一套（项目根内相对路径、realpath 防符号链接越界）；`/help` 列出全部指令；workspaceRegistry 缺席时 /sessions 与 /switch 回复「会话切换在当前环境不可用」。已知限制：/switch 目标会话若正绑定在其他 chat（其 runtime 仍在内存），当前实现直接复用该 runtime——审批卡与在飞卡片仍发往原 chat，且原 chat 的 /new 会取消该会话任务；请避免跨 chat 切换同一会话。摘除 runtime（retire / releaseUnbound / 覆盖失败清理）一律 dispose 宿主 AgentHandle 释放写句柄（接管来的 live 会话 dispose 为空操作，句柄归原主），否则自有会话永远 already owned 无法再 resume；live 检查与 resume 之间的竞态（恰好被他人打开）兜底回复「该会话正被占用（可能在 web 界面打开中），请关闭后重试」，绑定不变。

## 审批卡片与 ask_user

飞书审批卡片（0.2.9）：bot 会话工具提权经 `channels/approval/`（ApprovalCenter 渠道无关核心 + 飞书 presenter）处理——`ctx.on('approval/request', …, { prepend: true })` 抢在 web api-proxy 前、按 sessions map 过滤自有会话（非自有 next() 透传）；按钮回调经 WS 长连接 `card.action.trigger`（同 dispatcher 注册，toast 走应答帧返回值）；仅会话发起人可批（`SessionRuntime.initiatorOpenId` 比对）；发卡失败回退 next() 不吞审批；开关 `feishu.approval` 默认 true；扫码建应用 addons 含 `callbacks: ['card.action.trigger']`（存量应用需在开发者后台补开卡片回传）。bot 会话统一挂 agent-team preset，工具面含 `ask_user_question`（守护：`team-preset.test.ts` 断言生成 composition 保留 `tool-ask-user` 行、`bots/index.test.ts` 断言飞书应答端注册；引导文本断言见 `router.test.ts`）；渠道引导段 `dsh-agent-toolkit:channel:guidance`（`router.ts`，order 15）在 bot 自建/resume 会话注入（`/switch` 复用宿主内存 live 会话不重跑 setup，故不注入），文本引导模型「如需用户补充信息或做出决策，优先使用 `ask_user_question` 工具；该工具不可用时，直接在回复中提问并等待用户下一条消息」——原 `BASIC_TOOLS` persona 引导句已迁入此段，角色白名单收窄掉 ask_user_question 后仍成立。

飞书问答卡（2026-09-17 起 form 化统一提交）：镜像 `channels/approval/` 的「渠道无关核心 + 飞书 presenter」架构（`channels/questions/center.ts` 的 `QuestionCenter` + `questions/feishu.ts` 的 `FeishuQuestionPresenter`）；`ctx.on('user-questions/request', …, { prepend: true })` 抢在 web api-proxy 前、按 sessions map 过滤自有会话（非自有 next() 透传，web 会话照常浏览器作答），与审批 answerer 事件名不同互不冲突；开关 `feishu.questions` 默认 true。一次 `ask`（可含多问题）挂起为一个 key，**全部收齐才 resolve**；**仅会话发起人可答**（`initiatorOpenId` 比对，提交与文本同规则）；不超时；signal abort / 会话终结 → `ASK_ABORTED`，用户点「跳过本次提问」/ `dispose()` → `ASK_CANCELLED`（plan-mode 的 catch 依赖该错误类型把「用户取消评审」翻译成「留在计划模式等消息」；会话终结走 `retire()` → `agent.cancel()` 触发 signal abort，`dispose()` 仅在 `stopAll()` 调用）。卡片为独立互动卡（不进流式卡序列）：进行卡是单个 `form` 容器（name `q`，body 首元素），容器内每题渲染 markdown（问题 + plan-review intent（`exit_plan_mode`）的 `detail`，受 `cardMaxBytes` 治理、超长截断标注「完整计划见会话」）+ 选项题的 `select_static` 单选下拉 / `multi_select_static` 多选下拉（飞书卡片 2.0 无复选框组）+ 每题可选「其他」`input`（name `q{i}__custom`，对应答案 custom 字段）、开放题 `input`（name `q{i}`）；选择器/输入框不设 required、不挂 behaviors（选择缓存在客户端，提交时整表回调），提交按钮例外（form 内且必须挂 behaviors 回调路由 value），**name 用位置序号 q{i}**（q.id 是模型生成的任意字符串，飞书 form name 有字符与全局唯一约束）；「提交」（form 内 `form_action_type: submit`）与「跳过本次提问」（form 外 body 末尾常驻，form 内按钮只能 submit/reset 无法表达取消语义）常驻卡底。提交经 `card.action.trigger` 回调统一走 `form_value`（lark SDK `normalizeCardAction` 丢弃 `form_value`，渠道从 raw 的 `action.form_value` 直取进 `CardActionInput.formValue`）：`QuestionCenter.handleCardAction` 按位置序号聚合覆写 answers（单选字符串 / 多选数组 / 自定义文本；某题 formValue 全空则保留既有答案），**服务端全答校验**逐题判定「有选择或有自定义文本」（飞书原生 required 是「组件非空」，无法表达选项/自定义二选一，弃用）：缺答 toast「还有 N 道题未作答」且保持挂起，全答才 settle。value `{kind:'question', key, submit:true}` / 跳过 `{kind:'question', key, cancel:true}`；回调共用 dispatcher，按 value 的 `kind` 区分 approval/question（无 `kind` 视为 approval 存量兼容），pending 已摘的回调 toast「该问题已作答或已失效」。开放题仍支持 **inbound 文本拦截**（发起人下一条文本直接作答：不进排队队列、不触发新 turn，非发起人不拦截），但**不再 refresh 卡片**（form 卡无中间态，整卡重放会抹掉用户已填表单态）。提交/跳过/收齐后整卡定格为只读终态（无任何按钮，保留全部题目与回答、自定义答案截断至 200 字，cancelled 题未答标「已取消」），并经 `ReplyHandle.breakCard()` 关流当前流式卡 + 整卡重放，后续输出开新卡续接。发卡失败回退 next()（模型退回文字提问，引导段兜底）。2026-09-17 修复：初版用 `{tag:'action', actions:[button...]}` 容器承载按钮，card JSON 2.0 已禁用 action 容器（建卡报 200861「unsupported tag action」）导致发卡失败并静默回退 web 应答端（warn 在 dsh web 不可见，debugLog 事件后补才定位），现改 form 容器直排组件。spec：`docs/superpowers/specs/2026-09-17-feishu-question-form-card-design.md`。

bot 会话权限预设（0.4.2 起）：`feishu.permissionPreset` 配置宿主预设名（如 `danger-full-access`）后，bot 会话建账（create/冷 resume/web 存活接管/switch 冷接管，统一钩子在 agents-port adaptAgent/adaptLive）即经 `permissionPresets.set()` 应用该预设——完全权限、不再发起任何审批（审批卡路径不触发）；活跃复用与 /switch 命中插件内存会话不翻转存量状态；宿主 set() 幂等，重启 resume 重复应用无副作用；委派子会话自动继承父会话 sandbox override（宿主行为，零代码）。服务缺席/非法名 warn 降级不影响聊天。**默认值**：插件自带 cordis.patch.yml 的 insert 条目 config 默认下发 `danger-full-access`（schedule.permissionPreset 同）；schema 层无默认值——在 profile/home cordis.patch.yml 用同 id 覆盖 config 且不写该键即回落宿主默认审批（patch 语义整行替换 config，不写即 undefined）。安全警示：`danger-full-access` 下任何能给 bot 发消息的人（含群聊 @ 它的成员）即获宿主完全文件/命令权限，建议仅私聊 bot 启用。spec：docs/superpowers/specs/2026-09-15-feishu-permission-preset-design.md。
